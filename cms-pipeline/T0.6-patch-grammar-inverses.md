# T0.6 — Typed Patch Grammar + Inverses

**Phase 0 · depends_on: T0.2 · mode: auto · model: FABLE 5 · effort: xhigh**
**Blocks:** T0.7, and the review/Discard mechanism in T1.5.

## Why Fable / xhigh effort
This is the hardest correctness task in Phase 0. Every edit operation needs a provably-correct inverse so that "Discard" can cleanly undo it — including tricky cases (conditional upsert, slug-rename auto-aliasing). A wrong inverse silently corrupts data on undo. This is exactly the long-horizon correctness work Fable is built for. Set `/effort xhigh` at session start.

## Read first
`docs/cms-architecture/03-mapping-and-agent-contract.md` §2.0 (the op families), §2.3-taxonomy (the slug-rename alias rule), §2.4 (the conflict/blind-revert rule), and `02-architecture-and-schema.md` §3.1 (the content_revision bump rule).

## Context
Agents edit objects through typed operations, not free-form writes. Each op must record enough to be reversed, so the human-review Discard action (T1.5) can apply the exact inverse. This task defines the op grammar and the apply/inverse engine.

## Scope — files to create
- `src/schema/object-patch-ops.ts` (the op grammar)
- `src/lib/object-patch-apply.ts` (apply + inverse engine)

## Deliver
- The C§2.0 op families (page/section, navigation, taxonomy, site, template) as discriminated unions.
- Application captures `{before, after}` per op into history.
- **Inverse derivation per op**, including:
  - The conditional-upsert inverse: restore `before` when it existed, remove when it didn't.
  - The slug-rename auto-alias rule (C§2.3-taxonomy) — renaming a slug records an alias so old references still resolve.
- `content_revision` bumps **iff** an op actually mutates `body` (not on no-op or metadata-only ops).

## Non-goals
- No validation pipeline (T0.7) — this is apply/inverse mechanics only.
- No endpoint wiring (T0.8).

## Acceptance criteria
- Property-style unit tests: for **every** op family, `apply(op)` then `apply(inverse(op))` restores the prior body exactly.
- Blind-revert refusal: if `before` doesn't match current state, the inverse is refused (the C§2.4 conflict rule) — tested explicitly.
- A test proving `content_revision` bumps only when `body` changes.
- Committed to the working branch. No PR unless asked.
