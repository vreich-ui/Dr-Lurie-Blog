**Pattern distinction surfaced by S-3 (the one-line callout the brief requested, expanded by one sentence):** the model now has concrete examples of both reuse shapes. **`shared_ref`** = one object, many appearances — edit once, every page changes; one lock, one review, blast-radius surfaced at publish (homepage's `sec_newsletter_signup` if other pages ever reference it, D§2.5/C§2.3-section). **Independent instances of one component type** = same renderer and schema, separate data per page — per-page editing with no cross-page blast radius (`page_newsletter`'s own signup, S-3). Rule of thumb for future mapping choices: shared object when the _content_ must stay in lockstep; independent instances when only the _behavior/shape_ is shared. The `formName` staying identical across independent instances is what keeps downstream collection unified (`save-opt-in` mirroring is chrome-level and form-name-keyed, A§2.4).
