`docs/cms-architecture/10-admin-workspace-plan.md` §1 (principle 1) + §4, the T9.13 protocol (event types, `since_seq` polling), the T9.9 workspace layout.

## Context
The requirement that defines W9: "AI communication exchange front and center for every object," classic CMS UI promoted as the second option. The T9.9 forms page flips: chat takes the center, the inspector collapses into a "Details" drawer.

## Scope — files to create/modify
- Chat primitives in `src/components/admin-ui/`: ChatThread, ChatMessage, ToolCallCard (tool → human phrase + status), ApprovalCard (one-line summary + DiffView + dry-run result + Approve / Edit-and-approve / Deny), StreamingText, ChatComposer (readiness strip mounts directly above it).
- `src/pages/admin/content/[objectId].astro` layout flip: chat center, preview right, Details (T9.9 inspector) + History + Raw as a collapsed drawer; suggested prompts seeded from contract `editor.useWhen` + missing readiness criteria.
- Polling hook (`useChat`): `get_chat?since_seq` ~1s while a run is live, backoff when idle.

## Deliver
Chat-first object workspace: converse → approve → see the preview update → publish — with the forms one click away, never gone.

## Non-goals
- No cross-object hub (T9.17). No autonomy settings UI (T9.15). No SSE.

## Acceptance criteria
- Manual scripted conversation on a content_item and a page: propose-edit → ApprovalCard shows a human summary + real diff → Approve executes, Deny declines gracefully; Edit-and-approve round-trips.
- Suggested prompts reflect actual missing readiness criteria.
- `npm run check` + `npm test` green; public build-diff EMPTY.
- Committed to the working branch. No PR unless asked.
