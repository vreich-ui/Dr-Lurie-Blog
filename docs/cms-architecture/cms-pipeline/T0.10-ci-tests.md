# T0.10 — CI Enables the Test Suite

**Phase 0 · depends_on: none · mode: auto · model: Sonnet 5 · effort: low**

## Read first
`docs/cms-architecture/01-audit.md` §1.9 (the flagged gap: tests exist but CI never runs them).

## Context
The audit found the repo has a test suite that CI builds/type-checks around but never actually executes. Since Phases 0–1 are pure backend with no visual safety net, getting tests running in CI is foundational — every later task's "verify" step assumes CI will catch a regression. This can run independently and early.

## Scope
- `.github/workflows/actions.yaml` — **modify**: add `npm test` to the CI run.

## Deliver
`npm test` executes in CI alongside the existing build/type-check steps.

## Non-goals
- Don't rewrite the CI pipeline — add the test step, leave the rest.
- Don't make it a blocking merge gate configuration change beyond running the tests (branch-protection settings are a repo-admin action, out of scope for a code task).

## Acceptance criteria
- A CI run executes both the existing and any new suites.
- **Proof it actually gates**: on a scratch branch, introduce a deliberately-broken test and confirm the CI build fails. (Then discard the scratch branch.)
- Committed to the working branch. No PR unless asked.
