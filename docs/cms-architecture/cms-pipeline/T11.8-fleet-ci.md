# T11.8 — Fleet CI: per-site matrix (build, test, build-diff, drift guards)

**Phase 11 · depends_on: T11.6 · mode: auto · model: Opus 4.8 · effort: medium**
**Blocks:** T11.9, T11.11.

## Read first

`.github/workflows/actions.yaml` (current jobs), `scripts/build-diff.mjs`, the T11.1 placeholder matrix, T11.6's per-site drift guards.

## Context

"Canonical changes update all clients" is only true if CI proves every client on every core change. The matrix discovers `sites/*` dynamically — adding a client adds a matrix row with zero workflow edits.

## Scope — files to create/modify

- `.github/workflows/actions.yaml`: matrix over discovered `sites/*` × Node LTS — per site: install, `astro check`, build, full suite, site-seed drift guard; core-only test job runs once. Path filters keep site-content-only pushes from rebuilding the fleet needlessly (core changes always fan out).
- Per-site build-diff stage: on PRs touching `packages/core`, build each site at base vs head and run the normalizer diff; non-empty diffs surface as a review artifact (not an automatic failure — intentional visual changes are reviewed, per design-principles rule 4).
- CI time budget documented; cache strategy for the workspace install.

## Deliver

A core PR shows green (or a reviewable diff) for every client before merge.

## Non-goals

- No deploy automation changes (release stays the explicit verb per site). No schema gating (T11.9).

## Acceptance criteria

- CI green on the single-site fleet; a deliberate no-op core change demonstrates the fan-out; a deliberate site-content change demonstrates the filter.
- Committed `T11.8: …`; no PR.
