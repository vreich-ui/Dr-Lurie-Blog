# T0.5 — Generalized Lock Library

**Phase 0 · depends_on: T0.1 · mode: auto · model: FABLE 5 · effort: high**
**Blocks:** T0.8.

## Why Fable / high effort
This must exactly parity-match the existing article-locking semantics — lease durations, conflict codes, history behavior, counter-bump rules — against a *different* backing key, as a new file, without touching the original. Subtle divergence here (e.g. bumping the wrong counter) causes review-approval-invalidation bugs downstream that are painful to trace. Worth the stronger model. Set `/effort high` at session start.

## Read first
`docs/cms-architecture/01-audit.md` §1.2 (the full documented article-lock semantics — this is the spec to match) and `02-architecture-and-schema.md` §3.1 (the version vs content_revision counter rule).

## Context
Objects need checkout/lock the same way articles do. Rather than reusing the article lock (which is bound to article storage), this builds a parameterized lock library with identical semantics against any record key.

## Scope — files to create
- `netlify/lib/object-lock.ts`

## Deliver
`checkout / checkin / refresh / status / force_release` against a parameterized record key, with **semantics identical to the article lock**:
- 900s default lease / 3600s max lease.
- 423 conflicts, with sanitized holder info (never leak full holder identity).
- History entries on lock operations.
- **Each lock write bumps `version` but NEVER `content_revision`** (D§3.1) — this is the single most important invariant in the task.
- Implemented as a **new library**. `admin-workflow-lock.ts` is NOT modified — the article system stays untouched.

## Non-goals
- Do not modify, import from, or refactor `admin-workflow-lock.ts`.
- No verb endpoint wiring (T0.8).

## Acceptance criteria
- Unit tests asserting behavioral parity with the documented article-lock semantics, point by point.
- An explicit test proving "lock writes bump `version` but never `content_revision`."
- A conflict test returning 423 with sanitized holder info.
- Committed to the working branch. No PR unless asked.
