The workspace gets its frame: sidebar + topbar + Cmd-K shell, and the home page becomes the attention surface instead of a link grid. Legacy pages stay reachable during the transition.

## Scope — files to create/modify
- `src/layouts/AdminLayout.astro` (NEW) — static shell + client auth gate (same signed-out/forbidden/signed-in states as today's `index.astro`).
- `src/components/admin-ui/AdminShell.tsx` (NEW) — sidebar (Home, Content, Agents, Studio, Settings ▸ Guardrails/Admins, Profile, Maintenance, plus a "Legacy" group linking the old pages until W9.g), topbar with user chip, CommandPalette mount, Toast provider.
- `src/pages/admin/index.astro` — rebuild on the new shell: Release card (`admin-release` + `deploy-status` polling; first call often `build_not_confirmed_live` — poll, never re-fire), quick actions (new article / new page / open chat — stubs may link to legacy until their surfaces land), placeholder slots for the T9.11 inbox/activity widgets.

## Deliver
A signed-in admin lands on a modern home with working Release; all legacy pages remain reachable under "Legacy".

## Non-goals
- No inbox/audit data (T9.11). No content library (T9.8). No deletion of `AdminNav.astro` or legacy pages (T9.24).

## Acceptance criteria
- Manual flow: sign in → shell renders; Release card reflects a real deploy cycle correctly.
- Auth gate parity: signed-out and non-admin states behave exactly as before.
- `npm run check` + `npm test` green; public build-diff EMPTY.
- Committed to the working branch. No PR unless asked.
