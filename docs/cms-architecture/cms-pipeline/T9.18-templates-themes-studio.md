## Context
Requirement 8: top admins change/create themes, page templates, section templates. The studio is the visual browse/preview/apply layer over the W8 recipe family — Owner-tier per the RBAC matrix.

## Scope — files to create/modify
- `src/pages/admin/studio.astro` (NEW, on AdminLayout, Owner-gated UI + server checks already in place) — three galleries:
  - **Page templates (tpl_)**: card per recipe with the REQUIRED description/whenToUse/scope; "Use this template" → dry-run instantiate preview → confirm creates the page → its workspace.
  - **Section templates (stpl_)**: same, both modes (into an existing page under checkout, or standalone `sec_*`).
  - **Themes (thm_)**: palette swatches + typography specimen; "Apply theme" → dry-run diff of brandTokens (exact-replace op with stale-key nulls, per W8) → typed confirm → real `apply_theme` → publish/release prompts.
- "New recipe" actions open pre-seeded chats (T9.17 starters) or the blank object workspace — creation stays on the governed verbs either way.
- Surface `tpl_fieldtest`'s missing metadata trio as a visible "needs backfill (422 on patch)" badge rather than hiding it.

## Deliver
The recipe family browsable and appliable by an Owner without touching raw objects; REUSE-FIRST made visual.

## Non-goals
- No changes to instantiate/apply verb semantics. No composite sections (SPEC-ONLY behind OQ-W8-1…4).

## Acceptance criteria
- Manual: dry-run instantiate previews for a tpl and an stpl; theme apply dry-run diff matches the W8 exact-replace contract; Admin-tier user gets UI-hidden AND server 403 on apply.
- `npm run check` + `npm test` green; public build-diff EMPTY.
- Committed to the working branch. No PR unless asked.
