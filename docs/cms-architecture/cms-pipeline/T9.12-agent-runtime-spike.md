# T9.12 — Agent-runtime spike (throwaway)

**Phase 9 · depends_on: T9.1 · mode: notify · model: FABLE 5 · effort: high**
**Blocks:** T9.13. **Run as early as scheduling allows — this de-risks the project's central premise.**

## Why Fable / high effort
The whole chat-first design stands on one unproven mechanic: a Netlify background function running a provider agent loop that can PAUSE on a tool call, persist state, and RESUME after a human approval arrives on a different invocation. If that doesn't work within platform constraints (cold starts, 15-min budget, blob-store event-log latency), W9.d needs a redesign — find out in a throwaway harness, not in production code.

## Read first
`docs/cms-architecture/10-admin-workspace-plan.md` §6 (chat runtime row), `netlify/functions/run-publisher-agent.ts` (the existing `@openai/agents` usage), `netlify/lib/blob-store.ts`, Netlify background-function docs (`-background` suffix, 15-min budget).

## Context
Prove: (1) provider adapter (Anthropic default — OQ-W9-3; key exists) streaming a turn inside a background function; (2) an event-log chat doc in a blob store that a client polls with `since_seq`; (3) one read tool executing via `handleObjectVerb`; (4) one ask-gated write tool that pauses the run, survives the pause, and resumes correctly on an `approve` call — with the resume re-verifying the stored pending call.

## Scope — files to create (ALL marked throwaway, `spike-` prefixed)
- `netlify/functions/spike-agent-chat.ts` + `netlify/functions/spike-agent-run-background.ts` + minimal shared lib.
- A disposable driver page or script to exercise it against a deploy.

## Deliver
Working spike on a real deploy + a findings note (timing, cold-start behavior, event-write cadence, provider quirks, recommended caps) recorded in the task log / PR description — the note is the deliverable T9.13 builds from.

## Non-goals
- No product polish, no full tool registry, no UI beyond the driver, no guardrail config. Spike files are deleted by T9.13.

## Acceptance criteria
- On a deployed function: a chat turn with a read tool completes; an ask-gated write pauses ≥60s and resumes to a correct write with human-principal attribution in object history.
- A forged/mismatched resume payload is rejected (the re-verification mechanic proven here).
- Findings note written. Committed to the working branch. No PR unless asked.
