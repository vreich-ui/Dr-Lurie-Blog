## Context

brandTokens carries only colors + 3 fonts; all spacing/radius/shadow/type-scale/container styling is hardcoded CSS, so a theme can recolor the design system but not vary it. W10 widens the surface with **bounded enum axes** (rule 6: enumerated data → pre-built class/var mappings; never CSS strings).

## Scope — files to create/modify

- `src/schema/bodies/site-v1.ts`: extend `brandTokensSchema` with OPTIONAL `layout` / `shape` / `type` axis objects per plan §1.1 (all `z.enum`, `.strict()`); `theme-v1.ts` inherits via the shared schema (verify, don't fork).
- `src/lib/registry/theme-tokens.ts`: add `THEME_AXIS_KEYS` + per-axis allowed values + per-value class/var mapping tables; export defaults matching today's hardcoded look exactly.
- `src/components/CustomStyles.astro` (+ `tailwind.config.js` / `tailwind.css` where mappings must hook in): emit axis-driven custom properties or a `data-*` attribute per axis; wire the existing hardcoded tiers to read the default mapping. **Byte-identical default output is the gate** — with no axes set, the built site must not change.
- Enum values never reach the CSS-value string grammar; the safety helper (`checkBrandTokenValue`) is untouched for colors/fonts.

## Deliver

Axes parse on site AND theme bodies, render through code-owned mappings, default to today's look byte-exactly.

- No apply/validation/contract wiring (T10.2). No new section types. No changes to color/font semantics. No use of the axes on any live page.
