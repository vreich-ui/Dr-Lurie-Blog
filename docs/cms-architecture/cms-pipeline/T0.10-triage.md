# T0.10 triage — every failure classified before CI wiring

Per the T0.10 brief's mandatory triage step: every failing case was put into exactly one
of two buckets before `npm test` was wired into CI.

- **Bucket 1 (environmental)** — genuinely network/environment-dependent, to be
  skipped or mocked in CI specifically, case-by-case (never a whole file).
- **Bucket 2 (real bug)** — fixed, not skipped.

**Result: bucket 1 is empty.** Every failure that surfaced once the full suite was
made compilable and runnable — `tests/netlify/**` plus all `src/**/*.test.ts` files,
578 tests total, plus 5 more in the standalone `tests/scripts/validate-upload-images.test.mjs`
suite — root-caused to bucket 2. The file most likely to need mocking,
`tests/netlify/artifact-url-ingest.test.ts`, turned out to already fully mock DNS and
`fetch` (`t.mock.method(_ingestInternal, 'dnsLookup' | 'fetch', ...)`) — no live network
dependency exists anywhere in the suite (confirmed by grepping for unmocked `https?://`
usage across every test file).

The suite was never run end-to-end in CI before this task, so these bugs had simply
never been caught. Below is every fix, grouped by root cause, all bucket 2.

## 1. `req_*` request-id fixture format (dominant cluster — ~40+ individual cases)

Production code (`netlify/lib/artifacts.ts`: `createArtifactBlobKey`, `isValidArtifactBlobKey`)
strictly enforces the canonical `req_<flow>_<topic>_<yyyymmdd>_<nn>` shape via
`validateRequestId` with **no lenient/slugify fallback** — this is deliberate, pervasive
production behavior (see `src/lib/agents-naming.ts`), not a bug. Many tests predated that
enforcement and used ad hoc ids (`'request-with-store-failure'`, `'req-direct'`,
`'ingest-request'`, etc.) that the validator now rejects. Fixed by rewriting fixtures to
the canonical format, confirmed via a scratch script that the underlying save+lookup
mechanism works correctly given a valid id:

- `tests/netlify/artifacts.test.ts` — ~10 fixtures; the `'///'` test's premise was
  rewritten to assert outright rejection (empty-after-normalization ids must not
  silently fold to a generic fallback).
- `tests/netlify/artifact-index-listing.test.ts` — 2 fixtures.
- `tests/netlify/save-artifact.test.ts` — 17 sites, moved to a shared
  `uniqueRequestId(label)` helper (this suite hits the real local blob store with no
  reset between tests, so ids must also be unique); one suffix-concatenation bug fixed
  alongside it (a `${requestId}-content-type` construction that no longer produced a
  valid id was replaced with an independently-generated id).
- `tests/netlify/publish-artifacts.test.ts` — 14 sites, same `uniqueRequestId` helper.
- `tests/netlify/publish-by-time-media.test.ts` — 3 fixtures.
- `tests/netlify/mcp-error-handling.test.ts` — 2 fixtures (one root-caused through
  `migrateArtifactIndexes` → `isValidArtifactBlobKey` → `validateRequestId`).
- `tests/netlify/artifact-url-ingest.test.ts` — 5 fixtures at specific call sites (other
  literal `'test'`/`'ingest-request'`-style ids used only in rejection-path tests, where
  an invalid id is the point of the test, were deliberately left untouched).

## 2. `process.cwd()` no longer equals repo root under the CI compile layout

`tsconfig.test.json` compiles everything to `.tmp/ci-test/`, and the CI test run
executes via `cd .tmp/ci-test && node --test` for recursive test discovery — so
`process.cwd()` at test time is the compiled outDir, not the repo root. Two files read
repo-relative source files directly (`netlify/functions/*.ts` source, not compiled
output) using `process.cwd()`-relative paths and broke:

- `tests/netlify/object-store-auth.test.ts`
- `tests/netlify/publication-timestamp-contract.test.ts`

Both fixed with a `findRepoRoot()` helper that walks up from the compiled test file's
own `import.meta.url` looking for `astro.config.ts`, then reads via `REPO_ROOT` instead
of `process.cwd()`.

## 3. TS5097 import-extension errors (compile-time, NodeNext resolution)

`NodeNext` module resolution requires `.js` extensions on relative imports even in
`.ts` source. These files predated that enforcement in this compile configuration and
had never been compiled under it before (proving they'd never actually run in CI):
`src/lib/admin/article-path.test.ts`, `src/lib/admin/readiness-criteria.test.ts`,
`src/lib/article-content/input-bank.test.ts`, `src/lib/article-content/input-bank.ts`,
`src/lib/article-content/serialization.test.ts`, `src/schema/article-content-v1.test.ts`,
`src/schema/extension-integration.test.ts`. Fixed by correcting the extensions; no
behavior change.

## 4. Wrong test assertions (never previously run, so never caught)

`src/lib/admin/article-path.test.ts` asserted the wrong output for two cases
(`slugifyTitle("Lurie's Guide")` and a full `generateArticlePath` case). Verified against
`normalizeSlug`'s actual, already-correct, already-tested behavior in
`agents-naming.ts` (each run of non-alphanumeric characters becomes one hyphen) and
corrected the test's expectations to match — production code was not touched.

## 5. Node-id collision with the hard-coded `n_hero` special case

`tests/netlify/publish-artifacts.test.ts` used a body-image test node whose id
collided incidentally with `n_hero`, a hard-coded special id in
`to-markdown.ts`/`publish-article.ts` that suppresses inline image rendering unless a
hero-slot winner exists. Renamed the test node id to `n_bodyimage` (the node id schema
is `/^n_[a-z0-9]+$/i` — no underscores after `n_`, so `n_body_image` was tried first and
also rejected). Confirmed via grep that `n_hero`'s special-casing is intentional
production behavior, not touched.

## Explicitly out of scope

`mcp/save-json-blob-mcp/`'s own test package (`mcp/save-json-blob-mcp/test/*.test.js`)
is a separate npm package with its own `package.json` and no `node_modules` installed
by the root `npm ci`. `AGENTS.md` already documents it as "still useful for local
stdio/standalone HTTP tests, but not the production Netlify entry point" — left alone,
not wired into the root `npm test`.

## Final state

- `tsconfig.test.json` (new) compiles `netlify/**/*.ts`, `src/**/*.test.ts`, and
  `tests/netlify/**/*.ts` to `.tmp/ci-test/`.
- `npm test` (new `package.json` script): compiles via `tsconfig.test.json`, runs the
  compiled suite with a bare `node --test` (for recursive discovery) from `.tmp/ci-test`,
  separately runs `tests/scripts/validate-upload-images.test.mjs` (the one suite that
  depends on the native `sharp` binary and isn't part of the TS compile), cleans up the
  compiled output, and exits non-zero if either run failed.
- Result: 578/578 passing in the compiled suite, 5/5 in the scripts suite.
- Gate proven: on a scratch, uncommitted change, a deliberately-broken test
  (`assert.equal(1, 2)`) was appended to `src/lib/object-ids.test.ts`, `npm test` was
  confirmed to exit 1 with `not ok ... DELIBERATELY BROKEN sentinel for CI gate proof`
  and `# fail 1`, and the change was then discarded (`git status` confirms the file is
  back to its committed state).
