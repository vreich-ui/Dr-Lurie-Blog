# T14.1 — App-shell extraction (un-hardwire the build)

**Phase 14 · depends_on: T14.0 (soft — parallel-safe if login fix stalls) · mode: notify · model: Fable · effort: xhigh**
**Blocks:** T14.2+ (everything — no second deployment exists until the
build is per-site).

## Read first

`decisions/2026-07-26-platform-site-ruling.md` (R3 — the relaxed gate),
`sites/drlurie/site.config.ts` (the per-site bundle + its drift-guard
notes), `astro.config.ts`, `src/config.yaml` machinery,
`src/config/*` (remaining identity/binding modules), `w11-move-map.md`
(what already moved and how).

## Context

Today exactly one Astro build exists and it is hardwired to Dr-Lurie:
`src/` at the repo root IS the app, reading drlurie's config. For
`sites/platform` to deploy as its own Netlify project, the application
shell must live in `packages/core` with each `sites/<client>` a thin
build entry (own `astro.config`, own data root, own bindings) over the
same shell.

## Scope

- Move the shell: `src/` pages/layouts/glue, `astro.config.ts` machinery,
  config.yaml handling, and the remaining `src/config/*` modules
  (site-identity, site-binding, policy-bindings) into `packages/core` /
  `sites/drlurie` as ownership dictates (law → core; Dr-Lurie's values →
  its site dir).
- Each site's build entry: `sites/<client>` gains whatever minimal
  `astro.config` + entry the shell needs; `npx astro build` (or the
  workspace script) works per site.
- Keep the zero-drlurie lint green for everything that lands in core.
- Netlify build config: root `netlify.toml` continues building Dr-Lurie
  until T14.3 points the platform project at its own entry; don't break
  the live deploy.

## Gates (per R3 — relaxed)

Full suite green; `astro check` 0 errors; **both** drlurie and (once
T14.2 scaffolds it) platform build and render locally. `build-diff` runs
informationally — differences are reviewed and noted in state-of-play,
NOT auto-blocked. Dr-Lurie is an example, not a constraint.

## Non-goals

No visual redesign; no content changes; no repo split.

## Acceptance criteria

- One shell in core; per-site build entries; drlurie builds green from
  its entry. Committed `T14.1: …` (may be several stepped commits, one
  concern each, like T11.4/T11.6); no PR unless asked.
