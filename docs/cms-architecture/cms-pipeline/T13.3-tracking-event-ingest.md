## Context

Own-tracker events are validated, enriched, and forwarded to the owner's DB sink through a same-origin relay (session decision: first-party relay). commerce_event.v1 rules apply verbatim: append-only, additive-only, server authoritative / client lossy, PII-minimized. The function also serves as the region oracle for T13.6's consent gate.

## Scope — files to create/modify

- NEW `src/schema/tracking-event-v1.ts`: `trackingEventSchema` + `trackingBatchSchema` exactly per 12-plan §5.2 (event enum, nullable object refs, allowlisted `props` per event, visitor modes, consent flags, context; `project_id` documented server-stamped).
- NEW `netlify/lib/tracking-events.ts` (commerce-events sibling): event build/sanitize helpers, vhash/shash (`sha256(TRACKING_SALT + utc_date + ip + ua + project_id)`, 30-min session window), NDJSON serialization, blob append (`events/<yyyy-mm-dd>/<ts>-<uuid>.json`).
- `netlify/lib/blob-store.ts`: `getTrackingEventsBlobStore` (`tracking-events`, strong).
- NEW `netlify/functions/track-ingest.ts`: content-type-agnostic parse; batch ≤25 / ≤64KB; per-event drop (never all-or-nothing); object ids re-validated via `isObjectIdForType`; enrich (Netlify geo context — pin the exact accessor, UA, env `TRACKING_PROJECT_ID`, vhash/shash); forward NDJSON to `process.env[<endpoint_env>]` + Bearer `env[<auth_env>]`, 2s timeout, no retries; blob mirror on failure/`always`; same-origin only (reject foreign `Origin`); instance-local token bucket; fast 202. `GET ?mode=region` → `{country}`.
- `netlify.toml`: `[[redirects]] from="/api/t"` → `/.netlify/functions/track-ingest`, status 200, force.
- Tests: schema (valid/invalid per event kind), sanitizer allowlist, vhash daily rotation + IP discard, batch partial-drop, origin rejection, mirror-on-sink-failure, region mode.

## Deliver

`/api/t` accepts a valid batch and 202s; events reach the configured sink (mocked) or the mirror; no raw IP or email is ever persisted; region oracle answers from geo headers.
