# T9.9 — Object workspace v1: generated inspector, readiness, actions, history, lock

**Phase 9 · depends_on: T9.8 · mode: auto · model: FABLE 5 · effort: high**
**Blocks:** T9.10, T9.11, T9.14.

## Why Fable / high effort
The inspector is **generated from `object_contract`** — schema-driven form generation across ten body schemas and their patch-op mappings, with the deep-merge/null-out trap live on every discriminated-union switch. Getting the generation layer right once is the difference between "every type works" and ten bespoke fix-up sessions. Set `/effort high`.

## Read first
`docs/cms-architecture/10-admin-workspace-plan.md` §4, `src/lib/registry/object-contract.ts` (contract shape: body_schema, patch_ops arg schemas, constraints), `docs/cms-architecture/conversion-playbook.md` (**the trap table — mandatory**), `src/lib/edit-mode/verbs-client.ts` (`EditSession` — reuse, don't reimplement), `src/pages/admin/objects/[objectId].astro` (the machine-centered page this replaces + Wolf's in-source TODO at lines 54–68), `netlify.toml` (the `/admin/objects/*` redirect pattern to copy for `/admin/content/*`).

## Context
The forms parity floor: everything the old review page did, human-centered, plus generated field editing. Chat arrives in T9.14 and collapses this into the "Details" drawer — build the layout with that flip in mind.

## Scope — files to create/modify
- `src/pages/admin/content/[objectId].astro` (NEW) + `netlify.toml` redirect (`/admin/content/*` → the page, same pattern as `/admin/objects/*`).
- Workspace components in `src/components/admin-ui/`: header (display name, type/status badges, unpublished pill), action bar (Publish w/ "now"/explicit-time → `publish_by_time`; Submit for review; Approve w/ M-6 pin picker for gated types; Discard; Edit-on-site link; New variant for content_item), `ObjectInspector` (generated from contract `body_schema` + `patch_ops`: bounded controls only — enums→Select, taxonomy→TaxonomyPicker, images→artifact upload; saves via `EditSession.patch`; **explicit key-nulling on variant switches**), ReadinessList fed by `validate`, HistoryTimeline (`verbToPhrase`), LockBanner (+ Owner "Take over" → `checkin{force}` from T9.4), Raw tab (read-only JSON).
- Playbook field-name discipline: `object_checkout` → `.lockToken` + `.record_version`; `object_get` → `.record`.

## Deliver
Any of the ten object types opens, edits field-level through generated forms, validates, publishes, and shows human history — no naked ids.

## Non-goals
- No chat (T9.13/14). No live preview pane (T9.10). No deletion of `/admin/objects` (T9.24 — it stays reachable under Legacy).

## Acceptance criteria
- Scripted manual drive per type family: checkout → edit → readiness updates → publish → release banner (page, section, content_item, navigation, taxonomy, site, template, section_template, theme, product).
- A discriminated-union variant switch produces a patch with explicit old-key nulls (test on the op-builder).
- Approve on a gated type pins the exact publish action (M-6) and the pin renders human-readably.
- `npm run check` + `npm test` green; public build-diff EMPTY.
- Committed to the working branch. No PR unless asked.
