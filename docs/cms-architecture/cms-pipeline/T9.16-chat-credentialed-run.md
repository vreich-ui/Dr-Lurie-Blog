## Read first
`docs/cms-architecture/10-admin-workspace-plan.md` §4 + §10, the T9.13 protocol tests (what is already proven headlessly).

## Context
House convention: the chat system isn't shipped until an article goes end-to-end through it on production, driven by a signed-in human.

## Scope
No product code. A drive script/checklist committed under `cms-pipeline/`, executed on production (or a production-equivalent deploy) by Wolf or a designated admin.

## Deliver — the drive
1. From `/admin/agents`: "Write an article about X" → agent creates a content_item (dry-run card → approve), drafts nodes, sets taxonomy from the registry.
2. Per-write ApprovalCards show human summaries + diffs; at least one Deny and one Edit-and-approve exercised.
3. Readiness strip goes green; Publish via chat (ask card) → export commit; Release → live page verified.
4. Flip a guardrail on `/admin/settings/guardrails` (e.g. content_item → require-approval) → observe the behavior change in a second conversation; revert.
5. Verify audit: object history attributes every write to the human principal; activity feed reads as human sentences.

## Non-goals
- No fixes bundled in — findings become tasks.

## Acceptance criteria
- Every step observed and recorded in `state-of-play.md` (the wave-exit entry), including the live URL of the created article.
