## Read first
`docs/cms-architecture/03-mapping-and-agent-contract.md` §2.0 (the six safety checks) and `01-audit.md` §1.1, §1.6, §2.12 (the existing reader-safety, readiness-criteria, and artifact-trust helpers to reuse rather than reinvent).

## Context
Before any agent-proposed change is eligible for review, it passes six composable safety checks. This builds that pipeline generically, reusing existing article-side helpers where they already exist.

## Scope — files to create
- `netlify/lib/object-validate.ts`

## Deliver
The six C§2.0 safety checks as a composable pipeline:
1. **Per-type zod** (from T0.2).
2. **ID discipline** (from T0.3).
3. **Reference integrity**: page refs resolve; `shared_ref` targets exist and are sections; `route`-kind targets allowed per the Gap-Note-2 lifecycle; taxonomy strings resolve through `merged_into` aliases (D§5.5).
4. **Reader safety**: generalize the existing `assert-reader-safe` (A§1.1).
5. **Artifact trust**: Major-Key refs only — reuse the `admin-patch-workflow` validation helpers (A§2.12).
6. **Structural invariants**: ≥1 visible section on published pages; PageType allowed/required sections respected.

Return the readiness-report shape (grouped criteria, each `complete | warning | missing`), extending the existing `readiness-criteria.ts` conventions (A§1.6).

## Non-goals
- Do not add nav-specific rules here — those are T2.1 (which extends this pipeline).
- No endpoint wiring (T0.8).

## Acceptance criteria
- Unit tests per check, with a fixture for **each rejection case AND each warn-only case** separately (they behave differently — e.g. duplicate nav targets warn rather than reject, C§2.3).
- The readiness-report shape matches the existing convention.
- Committed to the working branch. No PR unless asked.
