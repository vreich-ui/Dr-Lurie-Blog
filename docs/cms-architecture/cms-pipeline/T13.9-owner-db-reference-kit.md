## Context

The owner runs the DB ("a DB to listen to triggers"). This repo ships only a reference kit: any HTTPS sink accepting `POST NDJSON + Bearer + 202` works; Postgres with `pg_notify` triggers is the reference. Docs + SQL + one replay script — nothing deploys from here.

## Scope — files to create/modify

- NEW `docs/cms-architecture/tracking-sink-reference/README.md`: the receiver contract (NDJSON batch, Bearer auth, respond 202 fast, idempotency on `event_id`, additive-only schema evolution per commerce_event.v1 rules), env contract (`TRACKING_SINK_URL`/`TRACKING_SINK_TOKEN`/`TRACKING_SALT` — per-tenant Netlify env, names referenced from `trk_<site>`), and the strategy-join recipe: ingest `src/data/site/articles/*.json` exports into a `node_strategy(project_id, object_id, node_id, strategy, intent, …)` dimension; engagement×strategy = JOIN on `(object_id, node_id)` (events carry node_id only — the leak-safe boundary, per OQ-W13-5's blessing).
- NEW `docs/cms-architecture/tracking-sink-reference/schema.sql`: `tracking_events` table (`event_id uuid UNIQUE` — idempotent replay; project_id/ts/event + object columns; jsonb consent/props/context; indexes `(project_id, ts)`, `(project_id, object_id, ts)`, `(project_id, event, ts)`, gin(props)) + `notify_tracking_event()` + `AFTER INSERT` trigger firing `pg_notify('tracking_events', …)`; a minimal NDJSON receiver sketch (any stack) in the README.
- NEW `scripts/tracking-mirror-replay.mjs`: read the `tracking-events` blob store for a date range, POST NDJSON batches to a sink URL arg honoring `event_id` idempotency; dry-run default; documented in the README. (Store client per `scripts/lib/object-store-client.mjs` conventions.)
- Tests: replay script unit tests (batching, dry-run, idempotent re-run against a mock sink).
