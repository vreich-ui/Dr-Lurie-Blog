# T0.3 — Per-Type ID Validators

**Phase 0 · depends_on: T0.1 · mode: auto · model: Sonnet 5 · effort: medium**

## Read first
`docs/cms-architecture/02-architecture-and-schema.md` §3.1 (the ID ceiling regex) and `01-audit.md` §1.9 (the `req_*` ID bug this task closes).

## Context
Each object type needs strict ID validation. There's a real existing bug here: a fallback path can mint `req_*` IDs that the system's own validation then rejects. This task makes generic object creation delegate to the existing article ID validator so it can never reproduce that bug class.

## Scope — files to create
- `src/lib/object-ids.ts`

## Deliver
- The D§3.1 ceiling regex, plus per-type strict validators.
- `content_item` IDs **delegate to `validateRequestId` verbatim** (from `agents-naming.ts`) — do not reimplement the rule. This is what prevents generic creation from minting artifact-incompatible `req_*` IDs (the A§1.9 bug class).
- Section-instance IDs match `/^s_[a-z0-9]+$/` (note the C§1.0 convention — no underscores inside the suffix).

## Non-goals
- Do not modify `agents-naming.ts` — import from it.
- No changes to the envelope or body schemas.

## Acceptance criteria
- Table-driven tests including the known-bad cases: `req_foo` must be rejected, `s_start_grid` must be rejected (underscore in suffix).
- Valid IDs for each type pass; malformed ones fail.
- Committed to the working branch. No PR unless asked.
