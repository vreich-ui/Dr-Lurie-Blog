## Why Fable / high effort
This is **security-boundary work**: role resolution feeds `publish-gate.ts` (the project's security boundary) and every new Owner gate. A subtle precedence bug here either locks Wolf out or silently over-grants. Requires exhaustive adversarial tests and pinned publish-gate behavior. Set `/effort high`.

## Read first
`docs/cms-architecture/10-admin-workspace-plan.md` §6 + §8, `netlify/lib/roles.ts` (the OQ-5 provisional model), `netlify/lib/admin-auth.ts`, `netlify/lib/publish-gate.ts` (READ ONLY — not modified), `netlify/lib/blob-store.ts`, `netlify/lib/object-lock.ts` + the `checkin` path in `netlify/lib/object-verbs.ts`.

## Context
First persistent identity store in the project. Two workspace tiers (Owner/Admin) on top of the existing role machinery; `ADMIN_EMAILS` becomes the permanent bootstrap-Owner fallback so lockout is structurally impossible.

## Scope — files to create/modify
- `netlify/lib/users-store.ts` (NEW) — `users` blob store; record schema per plan §8 (zod, `schema_version: 1`, audit array).
- `netlify/lib/roles.ts` — add `'owner'` to `Role`; new async resolver (users-store record wins; env allowlists as fallback; `ADMIN_EMAILS` ⇒ owner; owner implies admin+publisher; `status: 'disabled'` ⇒ no roles; agent principals ⇒ `[]` unchanged).
- `netlify/functions/admin-users.ts` (NEW) — verbs `me`, `update_me` (self, any admin), `list`, `set_role`, `disable` (Owner). Invite is T9.5.
- Callers migrate to the async resolver: `netlify/functions/admin-object.ts`, `admin-release.ts`, `admin-auth-state.ts` (returns the workspace tier).
- Owner gates added: `admin-blob-manager.ts`, `admin-blob-store-diagnostics.ts`.
- `netlify/lib/object-verbs.ts` — additive `{ force: true }` option on `checkin`: allowed only when resolved roles include `owner`; history-attributed takeover (OQ-W9-8).
- Tests: `tests/netlify/` — see acceptance.

Store + resolver + admin-users function + owner gates + force-checkin, with `publish-gate.ts` byte-untouched.
