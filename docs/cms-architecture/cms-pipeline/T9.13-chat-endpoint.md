# T9.13 — Chat endpoint productionized

**Phase 9 · depends_on: T9.12, T9.4 · mode: notify · model: FABLE 5 · effort: xhigh**
**Blocks:** T9.14, T9.15, T9.17, T9.22.

## Why Fable / xhigh effort
This is the largest and most security-sensitive W9 task: a full agent runtime whose tool registry can mutate production content under a human's identity. The approval protocol (pause/resume, forged-resume rejection), principal capture, budget enforcement, and contract-constrained tool args all have to be right in one pass — an error here is an unattended write path. Set `/effort xhigh`.

## Read first
The T9.12 findings note (mandatory), `docs/cms-architecture/10-admin-workspace-plan.md` §4 + §6, `netlify/lib/object-verbs.ts` (`handleObjectVerb` signature + principal handling), `src/lib/registry/object-contract.ts` (patch-op arg schemas — tool args derive from these), `docs/cms-architecture/conversion-playbook.md` trap table (encode into tool descriptions).

## Context
The in-house CMS Agents runtime: provider-abstracted loop in a background function, event-log persistence, HITL approvals, everything executing through the one verb core as the signed-in human.

## Scope — files to create/modify
- `netlify/functions/admin-agent-chat.ts` (NEW) — verbs: `create_chat`, `list_chats`, `get_chat?since_seq`, `send`, `approve_tool`, `deny_tool`, `cancel`. `send` verifies identity, captures the human Principal into the run record server-side, **resolves the object's dedicated agent profile (object → type → site default, plan §4a) and stamps it into the run**, enqueues the background run.
- `netlify/functions/admin-agent-chat-run-background.ts` (NEW) — the loop; 15-min budget; caps (max tool calls/turn, token budget, wall clock — start from the spike's numbers).
- `netlify/lib/agent/loop.ts`, `tools.ts` (the §4 registry: reads auto; draft writes/creation/publication ask; `apply_theme` ask + Owner-only; creation tools dry_run-first), `provider.ts` (**BOTH Anthropic and OpenAI adapters behind one interface — v1 requirement, Wolf 2026-07-16; provider/model come from the resolved profile, never hardcoded**), `profiles.ts` (NEW `agent-profiles` blob store: profile schema per plan §4a, assignments doc, resolution chain, seed a site-default profile per provider), `chat-store.ts` (new `agent-chats` blob store; event-log doc, `seq`-ordered).
- Delete the T9.12 `spike-*` files (importer-grep first).
- Tests (`tests/netlify/`): protocol level — forged resume rejected; deny path feeds refusal to the model; caps enforced; principal attribution appears in object history; tool arg schemas reject out-of-contract ops; disabled/non-admin callers 401/403; **profile resolution precedence (object beats type beats default) and run-record stamping (a mid-run reassignment never switches a live run); both provider adapters pass the same conformance suite**.

## Deliver
A production chat runtime any UI can drive: object-scoped chats (`obj:<objectId>`) and free-form chats, with approvals, budgets, and audit.

## Non-goals
- No UI (T9.14). No governance-store consumption (T9.15 wires adjustable autonomy; until then the §4 defaults are hardcoded). No SSE (polling v1; SSE is a marked seam).

## Acceptance criteria
- All protocol tests green; a scripted end-to-end conversation on a deploy: read → propose patch → approval card event → approve → write lands with human principal in history → publish (ask) → release banner state correct.
- `npm run check` + `npm test` green.
- Committed to the working branch. No PR unless asked.
