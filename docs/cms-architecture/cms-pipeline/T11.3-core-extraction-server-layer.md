## Context

Security-boundary task (hence notify/Fable): the verb core, publish gate, blob binding, and the MCP server become **factories parameterized by a site binding** (site id, store credentials env names, git repo/branch, build hook, auth token env) instead of reading module-level env directly. Each site's `netlify/functions/` shims instantiate the factory with its binding — same wire behavior, zero new write paths.

## Scope — files to create/modify

- Move `netlify/lib/**` per the map into `packages/core/server/`; introduce a `SiteBinding` type (ids + env-var NAMES, never values) resolved once per function invocation; thread it through store/verbs/publish/release/gate. Off-limits files (`publish-article.ts`, `admin-workflow-lock.ts`, article MCP tools) DO NOT MOVE and are NOT edited — they stay site-side under `sites/drlurie/` untouched, wired exactly as today.
- `sites/drlurie/netlify/functions/*.ts`: thin shims re-exporting core handlers bound to the drlurie binding; `netlify.toml` functions dir updated accordingly.
- Auth invariants preserved and pinned by tests: publish key never client-supplied; MCP token gate behavior identical (open when unset, constant-time compare when set); admin functions keep Identity auth; agent principals still resolve to no roles.
- Adversarial tests: cross-binding leakage (two bindings in one process never share store clients/secrets), missing-env fails closed per binding.

## Deliver

One core server implementation; Dr-Lurie runs on it via its binding; wire behavior byte-identical.

## Non-goals
