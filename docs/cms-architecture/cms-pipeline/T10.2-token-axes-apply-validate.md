## Context
T10.1 added the axes to the schemas and renderer. This task makes them governed: validated, applied atomically by `site_apply_theme`, and advertised to agents.

## Scope — files to create/modify
- `netlify/lib/object-validate.ts`: extend `checkTheme` + the site check — unknown axis key warns (inert), invalid enum value `blocks_write` (zod already rejects; keep criterion copy human-readable). A theme MAY omit axes (missing axis = default at apply; do NOT extend the 10-required-colors posture to axes).
- `netlify/lib/object-verbs.ts` (`site_apply_theme`): the computed exact-replace op covers axes — theme axis present → copied; theme axis absent → site axis UNSET (defaults win). Same one-op atomicity, history `applied_theme`, inverse-as-discard. dry_run reflects axes.
- `src/lib/registry/object-contract.ts`: constraint entries + workflow copy for theme/site mention the axes; `set_theme_fields` / privileged palette op arg schemas pick the new keys up from the shared schema (verify derivation, no hand-written drift).
- Reconcile driver (`scripts/lib/roundtrip-reconcile.mjs`): site branch continues to EXCLUDE brandTokens entirely (theme-only governance covers axes automatically — verify with a test, do not widen the exclusion by hand).

## Deliver
An agent can draft a theme with axes, dry-run and apply it, see exact-replace + inverse behavior, and read all of it from `object_contract`.

- No UI. No seed changes (T10.8). No weakening of `palette_theme_only`.
