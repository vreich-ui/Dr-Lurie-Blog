**Phase 12 · depends_on: T12.2, T12.3, T11.11 (landing zone = the target project's own store; T11.11 staging client when W11 is in place, else the target project's store directly, per OQ-W12-3) · mode: auto · model: Opus 4.8 · effort: high**

## Read first

`docs/cms-architecture/conversion-playbook.md` (call/response names + trap table — mandatory), the T12.2 mapping artifact + T12.3 theme draft formats, `netlify/functions/mcp.ts` verb tools (create/checkout/patch/validate/instantiate/apply dry_runs), `11-platformization-plan.md` §3 + OQ-W12-1/-3 rulings.

## Context

Everything the pipeline writes goes through the SAME MCP verbs any agent uses — no side door, no direct store writes. Output is entirely draft-state: pages, shared sections, section templates for repeated shapes, one theme. Nothing publishes, nothing releases.

## Scope — files to create/modify

- ✚ `packages/core/cli/capture/emit.mjs`: against the target project's own MCP endpoint (the T11.11 staging client when W11 is in place; otherwise the target project's store directly — per OQ-W12-3, everything lands as never-released drafts in the target project's OWN store, not a Dr-Lurie-only fallback): create the theme draft; mint `section_template`s for shapes repeated ≥ N times; create nav objects + pages (ordered sections from the mapping; routes from the discovered IA; route-collision handling via availability probes); `object_validate` after every create/patch — a validation failure quarantines that object into the run report, never "fixes" by loosening.
- Copy policy per the ratified OQ-W12-1 model (per-project, contract-owned): the target project's contract-declared copy-rights posture decides regenerate-vs-keep. The safe default when the contract is silent is to regenerate `source:'extracted'` text as original copy (model-assisted, same tone/structure); keeping extracted copy verbatim requires the target project's contract to declare content rights. The posture used is read from the contract (not a run flag inventing rights) and logged in the run report.
- Media: asset manifest entries become artifact-pipeline uploads via the existing intent/grant tools where rights allow; otherwise placeholder-free omission (fallback behavior per rule 3 — never invented content).
- ✚ Run report format: objects created, validation states, quarantines, gap-report refs, copy-policy used.

## Deliver

One command turns capture artifacts into a reviewable draft site inside the governed store.

## Non-goals

- No publish/release. No approval-policy changes. No writes to any site not named in the run.

## Acceptance criteria

- Dry-run mode prints the full op plan; live mode against the staging site produces validate-clean drafts (quarantines enumerated); run report committed for the fixture target.
- Committed `T12.4: …`; no PR.
