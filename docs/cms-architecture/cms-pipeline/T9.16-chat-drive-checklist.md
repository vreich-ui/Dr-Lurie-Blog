## The drive

1. **Create via chat.** `/admin/agents` → starter **New article** → tell the
   agent the topic ("Write an article about X"). Expect: the agent reads the
   inventory/registry, then proposes `create_object` — an ApprovalCard with a
   one-line summary AND a server-computed validation preview (dry-run).
   Approve. ☐
2. **Draft + taxonomy.** Let it draft nodes and set category/tags. Verify the
   terms it picks exist in the registry (it is instructed to check; novel
   terms will block publish later — that's the enforcement working). ☐
3. **Deny once.** On some proposed patch, press **Deny** with a reason.
   Expect: no write happens; the agent acknowledges and adjusts (the refusal
   is fed to the model). ☐
4. **Edit-and-approve once.** On another patch, press **Edit & approve**,
   change something small in the args JSON, approve. Expect: the write lands
   WITH your edit; the event feed shows "(edited)" and your identity. ☐
5. **Readiness green → publish → release.** Open the article's workspace
   (`Open <id>` button). The readiness strip above the composer must go green
   (fix via chat if not). Ask the agent to publish → approve the publish card
   → expect an export commit and "deploy stays deferred". Then Release from
   the workspace/home release card → verify the article LIVE at `/<slug>`. ☐
   Live URL: **********\_\_**********
6. **Guardrail flip.** `/admin/settings/guardrails` → set a chat tool (e.g.
   `checkout`) from ask → auto. Start a SECOND conversation on the same
   object: checkout now runs without a card (the FIRST conversation's live
   run keeps its frozen autonomy — that's the stamping rule, not a bug).
   Revert the flip. ☐
7. **Audit.** Object history: every write attributes to YOUR identity (the
   run principal), with approvals/denials and the approver on the chat
   events. The home activity feed reads as human sentences. ☐
8. **Dedicated-agent check (§4a).** In the roster, assign the GPT seed
   profile to the article's TYPE; start a new chat on a sibling object —
   the AgentChip shows the GPT agent; the original object (if
   object-assigned) keeps its own. Unassign; confirm fall-through. ☐
