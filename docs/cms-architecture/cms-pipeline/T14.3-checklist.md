## Step 1 — create the Netlify project (Wolf, token)

Either run this yourself with a token that can create sites:

```
node packages/core/cli/create-site.mjs --name platform --netlify-token $NETLIFY_API_TOKEN
```

…or hand the agent the token and it runs it. The command is idempotent about
the directory (`sites/platform/` already exists and is left untouched); the
token half creates the Netlify site, probes-provisions this site's own blob
stores, and pushes the auto-mintable secrets straight to the site's env store.
Generated secret VALUES are never printed or written to disk.

Project name is your pick — `platform`, or a prefixed variant if the bare name
is taken.

### Then, in the new project's settings — three things, once

1. **Base directory → `sites/platform`.** This is what makes Netlify read
   `sites/platform/netlify.toml` instead of the repo-root one, so it builds the
   platform entry into the platform `dist` with the platform function shims.
   Without it the project silently builds Dr-Lurie.
2. **Build command and publish directory** come from that file — confirm they
   read `npx astro build --config sites/platform/astro.config.ts` and
   `sites/platform/dist`.
3. **Enable Identity** (Netlify Identity → Enable). Then set `IDENTITY_URL` to
   the new site's `/.netlify/identity` and add yourself to `ADMIN_EMAILS`.

### By-hand env values the token step cannot mint

The CLI prints the full table with a ✓/☐ per row. These are the ☐ ones:

| Variable                               | Value                                                        |
| -------------------------------------- | ------------------------------------------------------------ |
| `NETLIFY_BUILD_HOOK_URL`               | create a build hook on the new project, paste its URL        |
| `GITHUB_REPOSITORY`                    | the repo `owner/name` — **after** the rename in step 4       |
| `GITHUB_BRANCH`                        | `main`                                                       |
| `GITHUB_CONTENT_TOKEN`                 | write token for the repo (the fleet machine account is fine) |
| `GITHUB_COMMIT_AUTHOR_NAME` / `_EMAIL` | committer identity                                           |
| `IDENTITY_URL`                         | the new site's `/.netlify/identity`                          |
| `ADMIN_EMAILS`, `ROLE_EMAILS_*`        | your address                                                 |
| `MCP_HTTP_AUTH_TOKEN`                  | a fresh per-site key                                         |
| `ARTIFACT_URL_INGEST_ALLOWED_HOSTS`    | policy choice; empty is fine to start                        |

Reuse the FLEET-SHARED values verbatim — do not mint new ones:
`PDF_TOOL_BASE_URL`, `PDF_TOOL_AGENT_RUN_TOKEN`, `PDF_TOOL_STORAGE_SITE_ID`,
`PDF_TOOL_STORAGE_TOKEN`, and the AI provider keys.

Also add `SECRETS_SCAN_OMIT_KEYS = "GITHUB_REPOSITORY"` — the same reason it is
on the Dr-Lurie project: the value is a plain typeable string and the scanner
fails the whole build on any appearance of it.
